# How results are scored and how uncertainty is computed

Everything here is regenerated by two scripts, without model calls:

```
python analysis/rescore_and_ci.py     # -> results/summary_ci.{csv,md}, results/paired_comparisons.csv, results/rescored/
python analysis/run_determinism.py    # -> results/run_determinism.csv  (needs read access to the DynamoDB table)
```

## 1. What is being estimated

Each cell (task × model × prompt) is a single run at temperature 0 over the **first N items** of a public
split: SST-2 validation[0:100], AG News test[0:100], TriviaQA rc.nocontext validation[0:100],
CNN/DailyMail 3.0.0 test[0:20]. The quantity of interest is the model's score on the whole split; the
uncertainty we report is from having observed only N items of it.

Caveat: the first N items are not a random sample. The CIs treat them as if they were, which is the
standard assumption but is not guaranteed for any given dataset ordering.

## 2. Why item resampling rather than repeated runs

`results/run_determinism.csv` compares repeated runs of the same config stored in DynamoDB
(2–5 runs per config, 23 configs):

* The stored score was **identical across runs in 17 of 23 configs**; the largest range was
  **6 points** (nova-micro, AG News, chain-of-thought).
* Raw outputs are *not* fully deterministic at temperature 0 on Bedrock, especially for long generations
  (e.g. only 3% of nova-micro AG News CoT outputs were byte-identical across runs).

At n=100 the item-sampling 95% CI half-width is roughly 8–10 points, so item sampling dominates; the
CIs below do **not** include run-to-run variation, which is small but non-zero for long generations.
(These determinism figures use the originally stored scores, i.e. legacy parsing.)

## 3. Intervals

Implemented in `harness/stats.py`, tested in `tests/test_stats.py`.

| Quantity | Method |
|---|---|
| Mean of per-item scores (accuracy, rates, exact match, ROUGE-L) | Percentile bootstrap over items, **B = 10,000**, 95% |
| Accuracy among items with a valid label ("selective accuracy") | Bootstrap of the ratio sum(correct·valid)/sum(valid), same resamples |
| Difference between two systems on the same items | **Paired** bootstrap: resample item indices once, apply to both systems |
| p-value for a paired binary difference | Exact two-sided McNemar (binomial on discordant items) |
| Multiple comparisons | Holm adjustment within each (task, metric, comparison-type) family → `p_holm` |
| Analytic cross-check | Wilson interval; agrees with the bootstrap to within ~1.5 points at n=100 (tested) |

**Seed handling.** Every interval re-seeds NumPy's PCG64 with `DEFAULT_SEED = 20261118`, so a given
(n, B, seed) always draws the same resample indices. Output is byte-reproducible and does not depend on
the order cells are processed in. A test checks ~95% empirical coverage on simulated Bernoulli data.

**Reading the numbers.** Results are written as `point [lo, hi]`. Percentile intervals can be asymmetric
(and collapse to `[0, 0]` or `[100, 100]` when every item has the same outcome — e.g. an invalid rate of
0/100 has interval [0, 0], which understates uncertainty; the Wilson interval for 0/100 is [0, 3.7]).
`summary_ci.csv` also has a `half_width` column = (hi − lo)/2 for "x ± y" reporting.

**Paired vs separate CIs.** Two cells' CIs can overlap while their paired difference is clearly non-zero,
because the same items are hard for both models. Compare systems with `paired_comparisons.csv`, not by
eyeballing overlap.

## 4. Scoring: legacy vs strict

The originally reported numbers ("legacy") came from parsers with two flaws, pinned by tests in
`tests/test_parsers.py`:

1. **SST-2:** the word "positive" anywhere in the output won. When Mistral hedged ("neutral") and then
   hallucinated further few-shot examples containing "Sentiment: positive", the hedge was scored as
   *positive*. Truncated chain-of-thought reasoning that merely mentioned "positive" was also scored.
2. **AG News:** substring scan over keyword lists in fixed label order (e.g. "game" → sports before
   "market" → business).

The strict parsers (`harness/parsers.py`) produce one of: a task label, `neutral` (sentiment hedge),
`ambiguous` (names more than one class, e.g. "science (or business, depending on the focus)"), or
`invalid` (no parseable label). Only a single task label can be correct.

* **zero/few-shot:** first word if it is a label (a leading class label is `ambiguous` if the first line
  also names another class); otherwise the first line if it names exactly one label. Text after the first
  line is ignored.
* **chain-of-thought:** last word if it is a label (the prompt asks the model to end with it); otherwise a
  label as the *first* word (answer-then-explain style). A label mid-sentence is not accepted, because in
  CoT that is usually truncated reasoning.

Tests assert that the legacy parsers reproduce **every** stored label (600 SST-2, 1,500 AG News), so the
legacy column is exactly what was originally reported.

**Known strict-parser limitations:** "business (specifically, technology business)" is scored
`ambiguous` because "technology" maps to the Sci/Tech class; a lone "politics"/"space" is `invalid` rather
than mapped to world/science. Both rules are deliberately conservative.

## 5. Results that are harness artifacts, not model behaviour

* **Chain-of-thought is truncated** (`maxTokens = 50` for classification). Llama-3-8B SST-2 CoT outputs are
  all 33–43 words, none contains an answer, so strict accuracy is 0% and legacy 42% was parser noise.
  No CoT number should be cited until re-run with a larger token budget.
* **Faithfulness is invalid as implemented:** the NLI premise is the first 800 characters of a
  2,000-character input. Not to be cited.
* **TriviaQA exact match penalises full-sentence answers** (Mistral/Mixtral); `contains_answer` is
  lenient and rewards verbosity. Both are reported; neither alone is a fair cross-model comparison.
